# Insurance Fixed-Income Portfolio Lab

A small portfolio-construction app built with FastAPI, Python, and PostgreSQL. It lets you set bond and issuer limits, run an optimizer, and inspect portfolio risk and performance in a browser.

This is a demo. The corporate bond universe and return history are generated by the app; they are not real market data. The ECB panel shows a daily euro-area AAA 10-year reference yield and does not provide live bond prices. The capital figure is a simple proxy, not a Solvency II SCR calculation.

## Run locally on Windows

Install Python 3.11 or newer. From this folder, run:

```powershell
.\run.ps1
```

The script creates a virtual environment, installs the packages, and starts the app on `127.0.0.1:8000`. Open the dashboard at <http://127.0.0.1:8000/> or the API docs at <http://127.0.0.1:8000/docs>. The local version stores data in `data/portfolio.db`. Press Ctrl+C in the PowerShell window to stop it.

## Run with Docker

Copy `.env.example` to `.env`, then replace both placeholder values with different random hexadecimal secrets of at least 32 characters. Keep `.env` private; Git ignores it.

```powershell
Copy-Item .env.example .env
docker compose up --build -d
docker compose ps
```

Open <http://127.0.0.1:8000/>. Enter the `API_KEY` value from `.env` in the dashboard and select **Use key for this tab**. PostgreSQL keeps its data in the `portfolio_db` volume. Stop the services with `docker compose down`; leave off `-v` to keep that volume.

## Using the dashboard

Set the duration target, rating floor, bond and issuer limits, liquidity and ESG screens, and risk aversion. Run the optimizer to see the holdings, exposure, risk, performance, and data-quality results. You can download the holdings as a CSV and rerun the portfolio with different settings.

## API routes

- `GET /api/v1/health` — database and sample-universe status
- `GET /api/v1/universe` — the generated bond universe
- `POST /api/v1/optimize` — optimize and save a portfolio
- `GET /api/v1/portfolio/current` — latest saved holdings
- `GET /api/v1/analytics/risk` — duration, volatility, VaR, and issuer exposure
- `GET /api/v1/analytics/capital` — illustrative capital proxy
- `GET /api/v1/analytics/performance` — portfolio and equal-weight sample comparison
- `GET /api/v1/analytics/quality` — missing data, reference-data checks, and MAD flags
- `GET /api/v1/analytics/ml-anomalies` — Isolation Forest flags for review
- `GET /api/v1/market-data/ecb-reference` — latest available ECB reference yield

API routes require the bearer key when `API_KEY` is set. The dashboard keeps the key in session storage for the current browser tab.

## How the calculations work

The optimizer maximizes yield with a variance penalty. It applies the duration band, rating floor, per-bond and issuer limits, liquidity and ESG screens, and optional energy exclusion. VaR uses historical simulation on the generated return series. The performance comparison uses an equal-weight portfolio of the same sample bonds, not an investable index.

The Isolation Forest is fitted to the generated returns and its output is cached until the data changes. Its flags are prompts to inspect the sample; they are not investment signals. The ECB series is daily TARGET business-day data, published around noon CET. It is displayed as context and is not used to price the corporate bonds.

## Run the checks

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

The tests cover portfolio constraints, infeasible settings, data-quality handling, analytics, and the anomaly-scoring code.

## Before using real investment data

Use an approved market-data provider and validate the model with the investment and risk teams. The capital proxy and sample-data analytics are not suitable for regulatory reporting. A production deployment would also need the organization’s identity, security, monitoring, and recovery controls.
